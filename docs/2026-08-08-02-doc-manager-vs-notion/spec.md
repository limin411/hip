# 「文档管理」× Notion / 飞书云文档 / 语雀 对比与改进方案 Spec（V2）

> 版本：v2.1（2025-08）
> **v2.0 核心变更（编辑模型重构）**：Notion / 飞书云文档 / 语雀 均为**实时 live 编辑器，无源码模式**。hip 文档编辑对齐该模型：**live 编辑器 = 唯一编辑表面，不做源码模式功能；Markdown 仅作存储层**（用户全程不见源码）。代码侧已有基础：`domain/knowledge/editorMode.ts` 注释明确 "Product path is always real-time Live (Notion/Feishu-style)"，`source` 仅为内部 fallback、`preview` 已废弃——本版把该方向**正式化并收口**。
> **v2.1（本次）**：**文档不承载元数据**——状态 / 标签 / 负责人 / 更新日期等一律不提供展示与编辑；frontmatter 仅作存储层内部字段（不提供任何元数据 UI）。
> 继承 v1.2 范围决策：数据库视图 / 导入导出 / AI 文档功能 / 云端能力 / 本地评论 / 自动备份 / 置顶 **均不做**。
> 样例文档：Notion 上的《智能体 Harness 工程研究报告》（长文 + Mermaid + 表格）。
> 配套文件：
> - [`plan.md`](./plan.md) — **完整执行计划**（P0/P1/P2 拆解、文件级任务、测试与验收、风险、PR 节奏）
> - [`tasks.md`](./tasks.md) — **细分任务清单与验收测试标准**（T1–T6 最小粒度任务 + 每条验收标准/阈值/运行命令）
> - [`editor-prototype-fullscreen.html`](./editor-prototype-fullscreen.html) — **全屏完整原型**（标题栏 + 侧边栏 + 实时编辑器 + 状态栏，内置 ⌘K 文档内跳转；浏览器直接打开即可编辑）
> - [`editor-prototype.html`](./editor-prototype.html) — 同引擎的带说明版原型（含参照产品对比条与交互清单）
> - [`mockup.html`](./mockup.html) — 视觉稿（⌘K 搜索、反链面板、编辑器补齐示意）

## 1. 定位声明（对比前提）

| | hip 文档管理 | Notion / 飞书 / 语雀 |
|---|---|---|
| 定位 | **本地优先**的单用户 AI 工作台文档模块 | 云端协作知识平台 |
| 编辑模型 | **实时 live 块编辑器，无源码模式**（本次收口） | 实时 live 编辑器，无源码模式 |
| 存储 | `~/.hip` 下 Markdown + YAML frontmatter（`tree.json` 管树）；**Markdown 仅是存储格式，不是编辑界面** | 云端私有块存储 |
| 不可让渡的底线 | Markdown 可读、离线可用、数据归用户 | 随处访问、实时协作 |

**结论先行（v2.0）**：编辑体验的参照系 = **Notion / 飞书云文档 / 语雀**——打开即编辑、所见即所得、全程不切源码。hip 的 live 模式已是产品主路径，本次做**收口**：删掉源码模式的用户入口（UI / 快捷键 / 命令面板 / 按文档记忆），把 `source` 降为纯内部兜底（大文档 / 解析失败），`preview` 代码路径清理；Markdown 往返保真成为**存储层硬约束**（`dialectRoundTrip` 测试守护），而不是一种编辑模式。

## 3. 决策与落地（V2-E0 编辑模型收口）

| 子项 | 现状 | 决策与动作 | 验收 |
|---|---|---|---|
| E0-1 源码模式入口 | `source` 可通过 `KNOWLEDGE_LIVE_FLAG_KEY` / `KNOWLEDGE_EDITOR_MODE_PREF_KEY` / `KNOWLEDGE_EDITOR_MODE_BY_DOC_KEY` 开启，存在模式切换路径 | **移除一切用户入口**：模式切换 UI、快捷键、命令面板项、按文档记忆（`editorModeByDoc` 读取逻辑退役）；flag 默认 on 且无关闭路径（代码可保留读取，但永不置 false） | grep 无用户可触达的 source 入口；文档注释说明 source = 内部兜底 |
| E0-2 preview 清理 | `preview` 已 deprecated（写入模式 normalize 为 live） | 删除 `mdPreview.ts` 相关写入模式与遗留状态；Typora 样式仅保留给阅读/导出 | `preview` 类型与引用清零（除历史兼容读取） |
| E0-3 存储层保障 | Markdown round-trip 存在已知 lossy 项（产品已接受） | round-trip **无损**列为存储层硬约束：`dialectRoundTrip` / `linkRoundTrip` / `frontmatterWrite` 测试清单化；已知 lossy 项逐条收敛（能修则修，不能修则写入存储规范 + 回归测试锚定） | 测试清单全绿；文档化「存储规范」 |
| E0-4 内部兜底 | source 用于大文档 / 解析失败 | **保留为纯内部 fallback**（无 UI）：live 渲染失败或文档过大自动降级，顶部非侵入提示「已进入兼容视图」，不提供手动切换 | 大文档（>1MB）打开不白屏，提示出现 |
| E0-5 阅读视图 | `DocReader` 已存在 | 保留只读阅读视图（对齐飞书/语雀阅读模式）；阅读视图非源码、不可编辑 | 阅读模式入口正常 |

**为什么不做源码模式**（与 Notion/飞书/语雀对齐的理由）：
1. 三个参照产品均已验证：live 编辑器 + 快捷键（`#`、`-`、`[ ]`、`>`）可覆盖 Markdown 输入效率，源码模式徒增心智负担与双模维护成本；
2. hip 的 Markdown 存储价值在「数据可读、可迁移、可被 Agent 直接读写」，不在「人对着源码编辑」——源码编辑与存储保真诉求冲突（源码改坏结构是 round-trip lossy 的最大来源）；
3. 开发者诉求由快捷键 + 斜杠菜单满足（对齐语雀键盘流），由 `editor-prototype.html` 原型验证。

## 5. 分维度对比与提案

### 5.1 编辑体验与块模型（hip 4 vs Notion 5）——本轮主项

**现状**（`DocBlockNoteEditor.tsx` + `domain/knowledge/blocks/`）：BlockNote 块编辑器（标题/列表/待办/引用/提示块/代码高亮/数学/Mermaid/图片题注/表格/附件/嵌入/内联 wiki 双链），斜杠菜单、拖拽手柄、Shift 多选；`live` 为主路径（`editorMode.ts`），`source` 内部 fallback，`preview` 已废弃；`DocReader` 阅读视图。

**提案 V2-E0（P1，编辑模型收口）**：见 §3 表格——移除源码模式入口、清理 preview、round-trip 无损硬约束、内部兜底、保留阅读视图。

**提案 V2-E1（P1，live 编辑器补齐，对齐 Notion 块体验）**：
| 子项 | 现状 | 目标 | 验收 |
|---|---|---|---|
| 分栏布局 | 无 | BlockNote 自定义 block：2–4 列，宽度拖拽 | 分栏内可嵌套任意块；Markdown 往返无损 |
| 块引用 | 仅整文档 wiki 链接 | 复制块链接（`#块id`）→ 悬停预览、点击跳转 | 长报告内「指向某章节」可直达并高亮 |
| 同步块 | 无 | 嵌入其他文档某块的只读镜像 | 源块修改，镜像跟随；可一键解除 |
| 模板变量 | 模板为静态 md | `{{date}} {{title}}` 插入时替换 | 新建文档从模板生成带日期标题 |

> **原型验证**：`editor-prototype.html` 已实现 live 编辑器核心交互（斜杠菜单、Markdown 快捷输入、拖拽排序、待办勾选、代码块、表格、分割线、自动保存指示），无任何源码模式入口。

### 5.2 结构化数据（hip 1.5 vs Notion 5）——⛔ 本轮不做
同 v1.2：Notion 数据库（属性集合 + 多视图 + 关系/汇总/公式）是最大差距，但与「Markdown 优先、零新格式」底线冲突；**且文档不承载元数据（v2.1）：状态/标签/负责人等不提供展示与编辑**，避免引入属性体系。现有表格块保留（frontmatter 仅作存储层内部字段，不提供元数据 UI）。V3 如启动，以「frontmatter 属性 + 文件夹即集合」为方向（git 历史 v1.0 V2-D1）。

### 5.3 导航与信息架构（hip 4 vs Notion 3.5，hip 反超）
单层级目录、↑ 返回、面包屑折叠 + 祖先跳转、浏览模式、`revealPath`、20 层深目录（V1.2 成果）。
**V2-N1（P0）**：侧边栏「最近文档」列表（`KnowledgeRecentItem` 已落盘，仅缺 UI）。置顶不做（v1.2 决策）。

### 5.4 链接、引用与图谱（hip 4 vs Notion 4）
wiki 双链 + 补全、`linkIndex`（入/出/断链/图谱）、图谱视图、大纲（数据已完备，UI 未充分暴露）。
**V2-L1（P1）**：右侧面板反链区块（目录下方，入链/出链/断链页签分组；曾置于文档底部，按需求移至右栏）+ 断链一键创建/重指向 + wiki 链接悬停预览卡。

### 5.5 检索与全局命令（hip 3.5 vs Notion 4.5）
MiniSearch 全文索引 + reveal 已就绪，但文档搜索与命令面板未打通、无最近混排。
**V2-S1（P0）**：⌘K 统一搜索（命令 + 文档 + 最近分组展示，回车 `revealPath` 直达；纯 UI 组装）。

### 5.6 导入导出与互操作（hip 3.5 vs Notion 4.5）——⛔ 本轮不做
现有文件夹导入（MD）、HTML/文本/zip 导出已覆盖迁移主路径；PDF/Notion 导入器/剪藏暂缓（git 历史 v1.0 V2-I1/I2/I3）。

### 5.7 AI 能力（hip 4 vs Notion 4.5）——⛔ 本轮不做
已有文档内 AI 动作（继续/总结/转任务/解释/重写）+ agent harness；不新增 AI 文档功能（git 历史 v1.0 V2-A1 归档）。

### 5.8 协作与评论（hip 1 vs Notion 5）——⛔ 本轮不做（含本地评论）
实时协作/评论/分享与本地优先定位冲突；本地块评论（原 V2-C1）单用户价值低，一并砍掉。

### 5.9 性能与规模（hip 4.5 vs Notion 3，hip 反超）
本地 IO、深目录 O(当前层)、内存索引。**V2-P1（P2）**：超大文档编辑器分片 + 大纲懒渲染；搜索索引增量更新。

### 5.10 可靠性与数据安全（hip 4.5 vs Notion 4，hip 反超）——保持现状
版本（每日/手动）+ 回收站保留期 + zip 导出已覆盖；自动备份/自愈（原 V2-R1）按 v1.2 不做。

## 7. 非目标（v2.1 范围决策，明确不做）

- **文档元数据**：状态 / 标签 / 负责人 / 更新日期等一律不提供展示与编辑；frontmatter 仅作存储层内部字段（v2.1 新增决策）；
- **源码模式功能**：模式切换 UI / 快捷键 / 命令面板项 / 按文档记忆；`source` 仅保留为内部兜底（v2.0 新增明确条目）；
- **Markdown 作为编辑界面**：Typora 式源码预览编辑、源码粘贴直编辑（粘贴 md 仍支持——粘贴即渲染为块，符合语雀/Notion 行为）；
- 数据库视图（表格/看板/日历/画廊）、relation/rollup/公式；
- 导入导出新能力（Notion 导入器 / PDF / 剪藏 / HTML 分享 / API）；
- AI 文档功能（问答/批量结构化/@文档）；
- 云端能力（实时协作 / 评论 / 分享 / 同步 / 账号）；
- 本地评论/审阅、自动备份快照/索引自愈、文档置顶。

> 各差距项记录见 §5 对应小节；V3 立项时复用 git 历史中 v1.0/v1.1 方案稿。

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| source 兜底路径残留导致双模维护成本 | 中 | E0-1 grep 清零用户入口；兜底路径保持最小（仅 live 渲染失败/超大文档两处触发）；文档注释声明 |
| 移除源码模式引发既有用户习惯反弹 | 低 | 快捷键 + 斜杠菜单覆盖 Markdown 输入效率（editor-prototype.html 验证）；`{{code}}` 代码块粘贴 md 自动分块 |
