## 1. 差距审计：为什么「奇怪」（代码出处）

文档管理主区的列表视图 = 一张四列表格（多选/图标/标题/更新时间/⋯）。逐格检查后，交互的怪异集中在**选择与打开共用一次单击**、**多选入口不可发现**、**规则分裂**三处：

| # | 差距 | 现状（代码出处） | 与 Notion 的差距 | 等级 |
|---|---|---|---|---|
| W1 | **批量态下单击语义突变** | `DocManagerBrowse.tsx:253` `openRow`：已有多选时，**普通单击 = 先清空全部选择、再打开文档**（`:278` 清空 + `openDoc`）——一次点击做两件相反的事，误触即丢选择 | Notion：选区态单击 = 选中/取消选中行；打开只由**双击**、Enter、或非选区态单击触发 | 大 |
| W2 | **多选入口不可发现** | 复选框列仅在 `selectedIds.length > 0` 时凭空出现（`:663` 网格 / `:768` 列表）；没有任何 hover 入口提示「可以多选」，用户只能靠猜 ⌘/Shift | Notion：行 hover 出现**六点手柄**，点按手柄 = 选中行（进入选区态），之后行首变为复选框 | 大 |
| W3 | **多选规则不一致** | ① 文件夹**不可多选**（复选框排除 `kind === 'folder'`）但可拖拽；② Shift 连选只在**非文件夹行之间**计算范围（`:271`），视觉却包含文件夹行——选区与视觉错位；③ 批量态下单击文件夹 = 清空选择并**直接进入文件夹**（`:255`） | Notion：页面与文件夹统一参与选择与批量操作 | 大 |
| W4 | **拖拽无手柄、整行可拖** | 整行 `draggable`（`:653` / `:759`），与文本选择、双击、滚动冲突；drop 语义按行类型分叉：文档行上下半 = before/after、文件夹行 = into（`hoverPos` `:205`）——同一手势三种结果，提示只有 2px 细线/描边 | Notion：**六点手柄 = 拖拽唯一入口**，拖起即显示插入指示线；整行点击不参与拖拽 | 中 |
| W5 | **新建行沉底** | 内联新建行渲染在列表**末尾**（`:853` `mt-3`），几十篇文档时完全不可见 | Notion：新建页面出现在列表**顶部** | 中 |
| W6 | **无表头、无排序** | 列表无表头行；展示顺序 = 树内 `order`，只能拖拽调序，无法按名称/最近编辑排序；更新时间列对文件夹显示静态文本「文件夹」（`:719` / `:824`），列语义不一致 | Notion：Name / Last edited 列头 + Sort 菜单（视图态排序，拖拽时自动退出） | 中 |
| W7 | **搜索弱** | 固定 160px 输入框（`:474` `w-40`）；无结果计数、无匹配高亮、无一键清空 | Notion：搜索聚焦全选、实时过滤、结果计数、可清空 | 小 |
| W8 | **批量条沉底遮挡** | 批量操作条为**底部居中浮动 pill**（`:902` `absolute bottom-4`），悬浮于内容之上，遮挡末行与拖拽落点 | Notion：选区态出现**顶部上下文条**，不遮挡内容 | 小 |

### 1.1 根因

W1–W3 同源：**选择（select）与打开（open）没有分离成两个独立手势**。代码把「点击」同时绑定了打开与清空选择两个动作，多选只能靠隐藏的修饰键进入，于是形成「复选框忽隐忽现 + 点击行为随状态突变」的怪异组合。W4–W8 则是「文件管理器心智」残留（新建沉底、底部浮动工具条、无表头），与 V2/V3 spec 声明的 Notion 参照系矛盾。

## 2. 目标与设计原则

### 2.1 一句话目标

> 文档列表的「选择 / 打开 / 组织」三件事彻底分离：**单击打开（非选区态）、点手柄选中、拖手柄组织**；多选入口永远可见，规则全类型统一——交互模型与 Notion All pages 对齐。

### 2.2 原则（在 V3 S1–S5、doc-ux-polish-2 S6–S7 基础上补充）

| 原则 | 内容 | 冲突裁决 |
|---|---|---|
| S8 选择与打开分离 | 选区态下单击行 = 切换选中（**永不打开**）；打开只由双击 / Enter / 非选区态单击触发 | 与「单击打开」现状冲突 → **本版裁决**：单击打开保留于非选区态；选区态单击改为选中，双击/Enter 打开 |
| S9 入口恒可见 | 行 hover 显示六点手柄（复用编辑器 `dot6` 视觉）+ 行尾 ⋯；点按手柄 = 单选（进入选区态），拖动手柄 = 拖拽；选区态行首手柄位变复选框 | 新增 UI 元素，视觉沿用 V3 中性暖灰，不新增 token 域 |
| S10 全类型统一 | 文件夹 / 文档 / 表格一律可多选、可批量移动/删除；Shift 连选按**可见行序**（含文件夹） | 与「文件夹不可多选」现状冲突 → 本版裁决：统一，删除 kind 特判 |
| S11 新建置顶 | 内联新建行渲染在列表/网格**首位**，而非末尾 | 无冲突（纯位置调整） |
| S12 批量条置顶 | 选区态出现工具栏下方**通栏上下文条**（N 项 · 移动到… · 删除 · ✕），不再底部悬浮 | 与 doc-ux-polish-2 S7「底部浮动批量条」冲突 → **本版裁决**：S7 的底部方案回退为顶部通栏（对齐 Notion，且不遮挡内容） |
| S13 视图态排序 | 列头排序为纯视图态（不改树 `order`）；激活排序时列表顶部显示排序 chip（可清除）；**拖拽行时自动退出排序态**（Notion 行为） | 与「展示顺序 = 树内 order」现状不冲突（排序是显示层过滤，`DocManagerSort.test.tsx` 语义保留） |

## 3. 整改项清单（文件级）

### P0 — 选择范式重做（核心）

**T1 选择与打开分离**（`DocManagerBrowse.tsx` `openRow` 重写）
- 现状：批量态单击 = 清空 + 打开（`:278`）。
- 改法：
  1. `openRow` 拆两段：**选区态**（`selectedIds.length > 0`）下单击 = 切换选中（文件夹同样 toggle，不再进入文件夹）；**非选区态**下单击 = 打开（文档/表格）或进入文件夹（现状保留）。
  2. 新增 `onDoubleClick`：选区态下双击 = 打开（文档/表格）/ 进入（文件夹）。
  3. Enter 键打开当前选中行（选区态下）。
  4. Esc / 点空白 / 全取消 退出选区态（现状保留）。

**T2 多选规则统一 + 入口可见**（`DocManagerBrowse.tsx` 行渲染）
- 现状：复选框仅非文件夹且已有选中时渲染（`:663` / `:768`）；Shift 范围排除文件夹（`:271`）。
- 改法：
  1. **删除 `node.kind !== 'folder'` 特判**：文件夹参与多选与批量操作；`deleteNodes` / `moveNodes` 已支持任意 id（`knowledgeStore.ts:482/484`），数据层零改动。
  2. Shift 连选范围改为**可见行**（`level` 全量，含文件夹）。
  3. **行 hover 显示六点手柄**（行首，复用编辑器 `dot6` 视觉）；**点按手柄 = 单选**（进入选区态）；**拖动手柄 = 拖拽**（mousedown 后位移 > 4px 判定为拖，否则为点选）。
  4. 选区态下行首手柄位替换为复选框（勾选视觉沿用现有）。
  5. 整行 `draggable` 移除，拖拽仅由手柄发起（消除与文本选择/双击的冲突）；`data-no-drag` 机制保留给行内交互元素。

**T3 批量条置顶**（`DocManagerBrowse.tsx` `:902` 浮动 pill）
- 现状：`absolute inset-x-0 bottom-4` 底部居中浮层。
- 改法：改为工具栏下方通栏细条（高度 40px，暖灰底 `--doc-row`，圆角 8px，`shadow-overlay`），内容不变：N 项 · 移动到… · 删除 · ✕；删除确认弹层、移动目录弹层复用现状组件。

### P1 — 组织与信息增强

**T4 新建置顶**（`DocManagerBrowse.tsx` `:853` 内联新建行）
- 现状：`newKind` 行渲染在列表末尾。
- 改法：内联新建行（含空态入口触发的）渲染到列表/网格**首位**；空态时居中（现状保留）。

**T5 列头与排序**（`DocManagerBrowse.tsx` 列表视图）
- 新增表头行（仅列表视图）：`名称`（默认「手动排序」）+ `最后编辑` 两列，右对齐于行内「更新时间」列位置；表头 hover 暖灰。
- 点击列头弹出排序菜单：手动排序 / 名称 ↑ / 名称 ↓ / 最后编辑 ↑ / 最后编辑 ↓；激活项打勾。
- 激活排序时：表头显示箭头指示；列表顶部出现排序 chip（`已按名称排序 ✕`），点击 ✕ 清除。
- 排序为显示层（`useMemo` 排序可见行，参照 `TableEditor` 的 `sortRowIndices` 思路），不改 `order` 不落盘；**拖拽手柄时自动清除排序**（恢复手动序，符合 S13）。
- 更新时间列：文件夹行不再显示静态「文件夹」文本，改为**子项数量**（`N 项`，`useMemo` 统计）；文档/表格保持最后编辑时间。

**T6 搜索增强**（`DocManagerBrowse.tsx` `:474` 搜索框）
- 现状：固定 `w-40`，无计数/高亮/清空。
- 改法：宽度 `w-40` → 焦点时展开至 `w-64`（transition）；输入时列表顶部显示 `N 个结果` 计数；匹配子串 `<mark>` 高亮（暖黄底，暗色降饱和）；输入框右侧 ✕ 一键清空并恢复完整列表。

### P2 — 网格一致性 + 微视觉

**T7 网格视图对齐**（`DocManagerBrowse.tsx` 网格分支）
- tile hover 顶部显示六点手柄（拖拽入口，替代整 tile 拖拽与点击的潜在冲突）+ 现有 ⋯ 按钮；选区态下 tile 角标复选框保留，单击 = 切换选中，双击 = 打开。
- 新建行置顶（与 T4 共用）。
- 暗色下抽查手柄/复选框/排序 chip 对比度 ≥ 4.5:1。

## 5. 非目标

- **知识表格编辑器**（`TableEditor` 轻表格的网格编辑交互）不在本版；其创建入口/浏览行形态随本版统一，但编辑器内交互保持 knowledge-table 系列现状。
- 数据库视图（Notion database / 属性列 / 分组 / 筛选）不做。
- 侧边栏 `DirNavList` 拖拽排序不做（doc-ux-polish-2 v1.1 已声明，保持现状）。
- 页面 emoji 图标（T14 暂缓，后续另行立项）。
- 回收站 / 归档 UI 不做（删除仍是现有回收站语义）。
- 不新增任何依赖（拖拽继续用 native HTML5 DnD 或 Pointer Events，不引 dnd 库）。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 选区态双击打开与单击 toggle 的判定延迟 | 选区态单击**不打开**，因此无 300ms 等待问题；双击判定用 `onDoubleClick`，单击 toggle 即时生效 |
| 手柄点选与拖拽区分 | mousedown 位移阈值 4px；超阈值进入拖拽态（行加拖影），否则 mouseup 触发选中 |
| 排序视图下拖拽的 order 语义 | 拖拽开始即清除排序态（S13），拖拽基于树内 order 计算 `toIndex`，语义与现状一致 |
| i18n 五语言（zh-CN/en/ja/ko/zh-TW） | 新增 key 集中在 `browse.*` 命名空间（排序菜单/计数/清空），`translation-keys.test.ts` 守护 |
