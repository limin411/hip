整改后高保真预览 · 对应 spec：docs/design/doc-notion-polish/doc-notion-polish-spec.md · chrome 保持 Flat Solid，仅文档域应用「纸张」子语言

根因为什么差距大

四个原因：① 文档区完整继承了全局「工具壳」语言（48px 顶部工具栏、常驻保存状态、面包屑）——Notion 是「一张纸」；② BlockNote 侧边菜单/气泡/checkbox 仍是框架默认形态，CSS 只做了表面扁平化；③ 排版参数继承自阅读器心智（15px/1.7/大段距），不是块笔记节奏（16px/1.5/4px）；④ 浏览视图是 Finder 式图标网格+表格。详见 spec §1。

智能体 Harness 工程研究报告
＋

本次调研围绕 Harness 工程的四个阶段展开：需求、架构、实现与验证。目标是把长任务拆解为可独立验证的阶段，并让每个阶段可被回放。

＋

一、背景与动机

＋

现有单轮对话无法承载跨天的复杂任务。Harness 引入「阶段 + 验收」模型：每个阶段输出必须通过门禁测试，失败则回到规划器修正。

＋
完成需求评审（2026-08-09）
搭建 Harness 骨架仓库
编写验收门禁的回归用例
＋

＋
typescriptconst harness = createHarness({
  phases: ['plan', 'verify'],
  gate: runUnitTests,
});
