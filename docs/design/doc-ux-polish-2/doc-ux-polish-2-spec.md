### 1.1 V3 遗留未完成项

| # | 差距 | 现状（代码出处） | 规格要求 | 等级 |
|---|---|---|---|---|
| G1 | 斜杠菜单尺寸未达标 | `BlockNoteHipSlashMenu.tsx:64` 仍为 `w-[min(100vw-2rem,18rem)]`（288px）；V3 验收清单自标注"待 T8 尺寸项（随后续微调）" | 356px 宽、46px 图标列、分组标题 12px 大写灰字、项高 40px、选中项暖灰 + 右侧箭头淡显 | 视觉 |

### 1.2 结构操作交互缺失（新增）

| # | 差距 | 现状（代码出处） | 规格要求 | 等级 |
|---|---|---|---|---|
| G4 | 浏览视图中文档**不能拖拽排序、不能移入其他文件夹** | `DocManagerBrowse.tsx` 行有 `data-no-drag`；无任何拖拽手势（**侧边栏拖拽本版不做**，见 §5） | 浏览列表/网格 tile 同层拖拽排序（改 `order`）；拖到文件夹行 = 移入（改 `parentId`）；拖到面包屑 = 移入祖先文件夹。**数据层已就绪，纯 UI 工作** | 交互 |
| G5 | 浏览视图**无多选/批量操作** | `DocManagerBrowse.tsx` 列表/网格行仅单选打开 + 行尾 ⋯ 菜单 | 多选（Shift 连选/⌘ 点选）→ 批量删除（确认弹层）/批量移动（文件夹选择弹层） | 交互 |

**关键事实（为什么 G4 成本低）**：
- `tree.ts` 的 `moveNodePure` 纯函数已实现「move node under newParentId at sibling index `toIndex`」，且注释明确支持「Dropping onto a doc: caller passes that doc's parentId and toIndex after the doc」；
- `knowledgeStore.ts:1526` 的 `moveNode(id, parentId, toIndex?)` action 已存在并接持久化；
- 删除复用 `removeNodeSubtree`（`knowledgeStore.ts:1568`），批量 = 循环调用；
- 全仓无 dnd 依赖库 → 采用 **native HTML5 DnD**（`draggable` + `onDragStart/Over/Drop`），`data-no-drag` 是现成的 opt-out 模式（防止与全局文件拖放冲突）。

| # | 差距 | 说明 | 等级 |

## 2. 目标与设计原则

### 2.1 一句话目标

> 把 V3 留下的「编辑器手势最后一环」与「结构操作交互」补齐：文档内拖拽像 Notion，文档管理（排序/移动/批量）不离开鼠标拖动与多选，全程视觉语言与 V3 纸面子语言一致。

### 2.2 原则（在 V3 S1–S5 基础上补充）

| 原则 | 内容 | 冲突裁决 |
|---|---|---|
| S6 拖拽手势 Notion 化 | 排序/移动统一走拖拽手势（限浏览视图）；拖拽中目标位置显示 **2px 指示线**（`--border-strong`），拖入目标行高亮暖灰；拖影 = 半透明行 | 与 Flat Solid 不冲突（指示线是纯功能反馈） |
| S7 批量操作轻量 | 批量态仅出现在浏览视图；批量条浮动于内容底部（复用 `kb-multiselect-bar` 视觉：暖灰底 + 圆角）；确认弹层复用现有对话框组件 | 不引入表格/属性选择等重 UI |

## 3. 整改项清单（文件级）

### P0 — 编辑器与菜单视觉/手势补齐（核心，1 周内）

**X1 斜杠菜单尺寸达标**（`BlockNoteHipSlashMenu.tsx` + `knowledge-blocknote.css`）
- 菜单宽 `18rem` → `22.25rem`（356px）；图标列固定 46px（图标居中于 30px 圆角块）；分组标题 12px 大写灰字（现有结构已接近，微调 padding）；项高 32px → 40px；选中项暖灰底（`--kb-hover`）+ 右侧箭头淡显。
- 验收：与 V3 preview.html §D7 一致；键盘导航（上下/Enter/Escape）回归。

**X2 手柄拖拽连续多选**（`DocBlockNoteEditor.tsx` + `knowledge-blocknote.css`）
- 现有 `kb-drag-handle`（2×3 六点 SVG）上：`mousedown` 后按住拖拽跨行 = 连续多选（Notion 手势）；选区行暖灰高亮（复用 `kb-multiselect`）；拖拽过程显示半透明拖影；松开结束。
- Shift+点击、块菜单多选入口**保留**（双入口，e2e 选择器不变）。
- 多选工具条（`kb-multiselect-bar`）补「批量删除」按钮（复用现有删除确认流程）。
- 验收：拖拽跨 3 行选中 3 块；工具条计数正确；`knowledge-multiselect.spec.ts` 回归。

### P1 — 结构操作交互（浏览拖拽与批量操作，1 周）

**X3 浏览视图拖拽**（`DocManagerBrowse.tsx`）
- 列表行/网格 tile 同手势（排序 + 移入文件夹行）；**面包屑行可作 drop 目标**（拖到 crumb = 移入该祖先文件夹）——单层模型下是跨目录移动的天然入口。
- 验收：列表内排序、拖入子文件夹、拖到 crumb 移入祖先，三种路径均持久化。

**X4 批量操作**（`DocManagerBrowse.tsx` + `knowledgeStore.ts`）
- 浏览列表行多选：Shift 连选 / ⌘ 点选；选中态 = 行左侧复选框 + 整行暖灰（与编辑器多选视觉一致）。
- 批量条（内容底部浮动）：显示 N 项 + 「删除」（确认弹层，复用现有确认组件）/「移动」（文件夹选择弹层，复用现有目录结构）；批量删除 = 循环 `removeNodeSubtree`，批量移动 = 循环 `moveNode`。
- 退出批量态：Esc / 点击空白 / 全部取消勾选。
- 验收：批量删除 3 篇文档 + 确认；批量移动跨目录；Esc 退出。

### P2 — 微视觉一致性（0.5–1 人日）

**X5 暗色与细节抽查**
- 暗色下：滚动条（细、低对比）、选区中性蓝灰、`--kb-*` token 对比度、代码块纸面调色板、多选高亮；
- 标题 hover ⋯ 入口延迟 **≤100ms**（防误触）；空态排版与 V3 一致；
- 不新增 token 域：全部复用 `--kb-*` / `--state-*` 现有变量。

## 5. 非目标（本版明确不做）

- AI 接入文档库（read/write/search_docs 工具、会话 attach）——独立方向，另行立项；
- **侧边栏拖拽排序与移动**（v1.1 裁剪；侧边栏行操作维持右键菜单 + hover ＋/⋯）；
- **页面 emoji 图标**（T14 暂缓；`frontmatter.icon` 保持模型预留，UI 零消费）；
- 嵌套层级侧边栏、跨文件夹拖拽的树形展开（v1.2 单层级决策保留；本版拖拽仅在同一可见层内 + 拖入可见文件夹/面包屑）；
- 数据库/元数据 UI（v2.1 决策保留）；
- Notion 导入/导出（保留）；
- 引入任何新依赖（dnd 库、emoji 库均不引入）。

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| native DnD 与全局文件拖放冲突（拖文件进窗口 = 导入资产） | 高 | 复用现成 `data-no-drag` 模式：行内交互元素全部标记；拖拽开始时置 `data-dragging` 标记，全局 drop 处理器检测后忽略 |
| 手柄 mousedown 与既有点击菜单/Shift+点击逻辑冲突 | 中 | 拖拽判定阈值（位移 >4px 才进入拖拽，否则保持点击语义）；PR-2 与 e2e 适配同一 PR 提交 |
| 拖拽排序与保存并发（乐观更新回滚） | 低 | 复用现有 `moveNode` action（已含持久化与回滚路径），不新增写入通道 |
| 批量删除误操作 | 低 | 确认弹层强制；批量条计数可见；支持 Esc 取消 |
| 暗色 token 新增泄漏到 chrome | 低 | 沿用 V3 纪律：`--kb-*` 仅挂载文档域作用域；X5 全部复用现有变量 |
