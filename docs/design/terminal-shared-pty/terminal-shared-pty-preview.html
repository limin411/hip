共享终端协同 — 围栏执行主路径T1 · P0

agent 提议 → 审批 → 围栏写入共享 PTY → 围栏退出码命中 → 命令卡 exit chip。OSC 633 marker 被 xterm 渲染层吞除，用户无感。

看点：① 终端里只出现命令与输出，OSC 633 marker 不可见；② 命令卡显示 exit 0 chip——退出码来自围栏而非猜 prompt；③ 输出按命令块切分，用户自己的输入不进 agent 上下文。

接管 / 交还（take the wheel）T2 · P0

agent 卡在 sudo 密码 → 用户直接在共享终端输入 → 飞行置 handed_off（deadline 暂停）→ 交还后 agent 重读 ring 恢复。

看点：① 无输出超阈值 → 信息性横幅「命令可能需要你介入」；② 用户键入 → driver=user，横幅变「你正在输入」；③ 点「交还」→ agent 恢复，结果标记 user_interleaved。

长命令 + 用户消息排队T3 · P0

agent 跑 npm run build（wait 120s）期间用户提交消息 → 暂存并标记 queued → 命令结束自动投递（Warp queued prompts 同款）。

看点：① 输入框下方出现「命令运行中 — 消息将在结束后发送」；② 消息卡带 queued 标记；③ 命令结束（exit 0）→ 消息自动投递，agent 继续处理。

完成判定对照 — 围栏信号 vs 猜 promptT1/T6 · P0

同样一个 df -h，正则启发式在三个真实场景下翻车；围栏（OSC 633 语义）全部命中，且自带退出码。

围栏信号 · OSC 633命令边界 + 退出码（VS Code / Warp 同款）
机制：写入时包裹不可见 OSC 序列；xterm 渲染层吞 marker；ring 保留原文供解析。无 marker（被 strip）时自动降级 prompt 兜底。
printf '\x1b]633;A\x1b\\'\n$ df -h\nFilesystem Size Used Avail Use% Mounted\n/dev/sda1 196G 42G 145G 23% /\n\x1b]633;D;0\x1b\\\n$
✓extractFenceExitCode → exit 0 → completed
PASSp10k 自定义 PS1（图标结尾）、输出被 ring 裁剪、命令无输出——全部靠 marker 命中，不依赖 prompt 长相。
正则启发式 · hasPromptTail现状，三个翻车现场
漏判p10k / starship 自定义 PS1：最后一行是图标 + 转义序列，[$#%>]\s*$ 不匹配 → 干等 deadline → timed_out + mayStillRun
误判输出以 $ 结尾：echo $? 的输出恰以 $ 收尾 → 命令还在跑就被判 completed
误判ring 裁剪：长输出超过 2MiB 被 trim，prompt 已不在最后一行 → 同样漏判
✗三条路径都拿不到 exitCode，agent 不知道成败
✅结论：围栏把「猜」变成「读」——命令边界与退出码成为协议信号；hasPromptTail 降级为无 marker 时的兜底（降级路径由真实 bash 夹具 T6 覆盖）。
