## 1. 背景与问题

### 1.1 现状

当前应用以「知识库」承载文档能力，层级为 **知识空间（space）→ 文件夹 → 文档/画板**：

| 层级 | 概念 | 现实现位置 |
|---|---|---|
| L1 | 知识空间（知识库） | `KnowledgeSpace { id, name, icon? }`，磁盘 `knowledge_index` |
| L2 | 文件夹 | `KnowledgeNode { kind: 'folder', parentId }` |
| L3 | 文档 / 画板 | `KnowledgeNode { kind: 'doc' / 'board', parentId }` |

- 侧边栏「知识库」段：仅展示 **空间平面列表**（`AppSidebar.tsx` 中 `filteredSpaces.map(...)`），目录树藏在主页面内（`KnowledgeWorkspace.tsx` 左侧 280px 面板）。
- 主页面：左侧空间树 + 面包屑 + BlockNote/Markdown 编辑器。

### 1.2 问题

1. **「空间」概念冗余**：大部分用户只有一个知识库，多一层 L1 只增加心智负担与操作成本（先建库 → 再进库 → 才能建文件夹）。
2. **侧边栏不成目录**：侧边栏只列空间，看不到文件夹/文档；用户必须进主页面才能浏览目录，不符合「像电脑文件夹一样」的预期。
3. **命名歧义**：「知识库」与「知识空间」混用（`知识库`/`新建知识库`/`知识空间`/`我的空间`），文案不统一。
4. **缺少"返回上一层"心智**：树视图可以一直点深，但缺少文件管理器式的**向上导航**（↑ 按钮 / 面包屑联动）。

### 1.3 目标

- **删除空间层**：全库合并为 **一棵统一目录树**，根即「文档管理」。
- **功能改名**：「知识库」→「**文档管理**」，全部文案、图标、命令面板、快捷键入口同步替换。
- **侧边栏即文件目录，且为单层级导航**：像本地电脑的文件管理器一样，**每次只显示当前层级的文件夹与文档**，点文件夹进入、↑ 返回上一层；不再渲染递归整树（深目录无性能/可读性问题）。
- **深目录友好**：面包屑折叠跳转 + hover 全路径，20+ 层深度同样流畅。
- **可返回上一层**：主区与侧边栏均提供 ↑「返回上一层」+ 可点击面包屑。

### 2.1 侧边栏（改造重点：单层级目录导航）

**核心原则：侧边栏不是递归整树，而是「当前位置的单层级视图」——与电脑文件管理器（Finder 列表视图 / Windows 资源管理器）一致：只显示当前文件夹的内容，进入下一层或返回上一层通过导航操作完成。**

| 元素 | 说明 |
|---|---|
| 导航项 | 图标 `BookOpen` → **`FolderTree`**；label `知识库` → `文档管理`；badge 计数为「顶层条目数」 |
| 导航条（列表区顶部） | `[↑ 返回上一层]` + **迷你面包屑**（当前路径，可点任意段跳转） |
| 列表区 | **当前层级的条目**：文件夹 `📁`（无展开箭头）与文档 `📄`、画板 `🖼` 平铺一行一列；文件夹优先、按修改时间倒序；点击文件夹 = 进入该层级 |
| 顶部操作 | `+` 新建（下拉：新建文件夹 / 新建文档 / 新建画板），在当前层级就地命名 |
| 搜索 | 过滤**当前层级**（与主区搜索同域，同一输入联动） |
| 右键菜单 | 打开 / 在此新建 / 重命名 / 移动… / 删除（去掉空间级项） |
| 空状态 | 当前层级无条目时显示「此文件夹为空」+ 主按钮 |

**导航模型（状态单一来源）**：`state.path` 为当前路径栈（`[root, …, 当前文件夹]`）。侧边栏列表 = `children(path.top)`，主区浏览视图 = 同一集合的详细展示；任一处导航（侧边栏、主区面包屑、↑、历史）都同步两侧。

**与主区联动**：点文件夹 → 主区进入浏览模式；点文档 → 主区打开阅读/编辑视图；↑ / 面包屑 双向同步。

### 2.1.1 深目录（20+ 层）规格

递归整树在 20 层深度下既难读也浪费（N 层 × 每层渲染）；单层级模型天然解决：**任意深度下侧边栏只渲染 1 层（O(当前层条目数)）**。

| 场景 | 行为 |
|---|---|
| 进入深处 | 逐层点击，每层一次渲染，无卡顿；路径实时反映在迷你面包屑 |
| 返回上一层 | ↑ 按钮 / 迷你面包屑任一段 |
| 跨层回溯 | 不提供前进/后退（已删除）；回溯靠 ↑ 与面包屑任一段跳转 |
| 面包屑溢出 | 超过 3 段自动折叠为 `全部文档 ▸ … ▸ 当前`；点击 `…` 弹出**祖先跳转菜单**（自上而下列出全部祖先，可滚动） |
| 路径可见性 | 面包屑行 hover 显示完整路径 tooltip（20 层全路径） |
| 深链直达 | 文档/文件夹支持「复制路径」，可在主区搜索框粘贴直达（`revealPath`） |

### 2.2 主内容区（新增"浏览模式"）

主区拆为两种模式，均由面包屑定位：

**A. 浏览模式（目录内容视图，本方案新增）**

```
[↑ 返回上一层]  全部文档 ▸ 产品手册 ▸ 用户指南    [搜索] [视图切换 网格|列表] [+ 新建]
───────────────────────────────────────────────────────────
📁 快速开始-素材        📁 截图               📁 规范模板
────────── 文档（6 篇）──────────────────────────────────────
📄 快速开始.md    Markdown  2.1 KB  2025-08-02 10:24
📄 安装部署.md    Markdown  4.8 KB  2025-07-30 16:41
🖼 产品路线图画板  画板      —      2025-07-28 09:12
```

- 文件夹优先排序，其次按修改时间倒序（与 `tree.ts` 的 `compareNodes` 语义一致）。
- 网格视图：文件夹卡片 + 文档卡片；列表视图：表格（名称 / 类型 / 大小 / 修改时间）。
- 顶栏最左为 **↑ 返回上一层**（Finder/资源管理器同款），禁用态：已在根目录。

**B. 文档视图（复用现有编辑器）**

- 点击文档/画板 → 进入现有 `DocEditor` / `KnowledgeDocCanvas`，顶部仍是面包屑 + ↑，可一步回到所在文件夹。
- 阅读模式（`DocReader`）保持不变。

### 2.3 面包屑与"返回上一层"规格

```
[↑]  全部文档 ▸ 产品手册 ▸ 用户指南 ▸ 快速开始
      (根)     (L1)      (L2)      (当前文档)
```

| 交互 | 行为 |
|---|---|
| 点击 ↑ | 回到当前层级（文件夹或文档）的父目录；在根目录时置灰（侧边栏与主区各一枚，行为一致） |
| 点击面包屑某段 | 直接跳转到该层级（= Finder 行为）；`…` 段弹出祖先跳转菜单 |
| 键盘 | 无目录历史快捷键（前进/后退已删除）；`Esc` 关闭菜单 |
| 标题栏拖拽 | 文件夹支持拖到面包屑某段上 = 移动到该目录 |
| 历史记录 | 每次路径变化（进入/返回/跳转）压栈，上限 100；复用现有 `navBack/navForward` 机制（`sidebarActions.ts`） |

## 3. 数据模型与迁移

### 3.1 新模型（v2）

```ts
// domain/knowledge/types.ts
export type KnowledgeNodeKind = 'folder' | 'doc' | 'board'

export interface KnowledgeNode {
  id: string
  parentId: string | null   // null = 根目录（原 spaceId 删除）
  kind: KnowledgeNodeKind
  title: string
  order: number
  createdAt: number
  updatedAt: number
}

// KnowledgeIndex v2：删除 spaces 数组
export interface KnowledgeIndex {
  version: 2
  root: { updatedAt: number }   // 根目录元数据（后续可放根级设置）
}
```

- 磁盘布局：`knowledge_index.json`（v2）+ 单一 `tree.json`（v1 结构不变，`nodes` 为全库节点）；文档正文路径由 `space/<spaceId>/docs/...` 变为 `docs/<nodeId>.md`（或保留 `docs/<id>` 哈希目录），资产、版本、回收站路径同步去掉 space 段。

### 3.2 迁移（保留为备选，本期不实现）

> **开发环境决策（2025-08-08）**：不做迁移。旧知识库文件已直接删除：`~/.hip/knowledge/`（v1 索引 + 空间数据）与 `~/.hip/trash/knowledge/`（回收站条目）。本节流程仅作为将来生产数据升级的备选方案：

1. 读取 v1 `knowledge_index` 与各 space 的 `tree.json`。
2. 合并：**每个旧 space 变成一个顶层文件夹**（`kind:'folder'`，title = space 名，icon 映射为文件夹图标或保留 emoji），其子节点整体挂入。
3. 重写节点 id 冲突（space 间 id 前缀不同，实际冲突概率低；冲突时 `slugify` + 随机后缀）。
4. 旧 `recent` 列表：`spaceId` 段改为指向新顶层文件夹 id；`wiki 链接 / 双链索引 / 搜索索引 / 回收站条目` 同步重映射。
5. 写入 v2 索引并标记 `migrationDone`；失败时回滚并保留 v1 备份（`knowledge_index.v1.bak`）。
6. 迁移完成后触发一次全量搜索索引重建。

> 保守策略：**不自动合并**，而是迁移为「每个旧库 = 顶层文件夹」，用户可手动拖拽合并——零数据风险，且完全符合"像文件夹一样"的操作直觉。

### 3.3 删除的能力与 UI

| 原能力 | 处理 |
|---|---|
| 新建/重命名/删除知识空间（`knowledge_create_space` 等 + `KnowledgeSpaceDialogHost`） | **删除**；对应的 Rust 命令保留为迁移用，UI 不再暴露 |
| 空间图标选择（`SpaceIconPicker`） | 删除；文件夹默认 📁 |
| 空间级右键菜单（`context-menu/providers/knowledgeSpace.ts`） | 删除，合并进目录树菜单 |
| 空间级回收站（`KnowledgeTrashKind 'space'`） | 降级为普通文件夹回收 |

## 5. 交互规格补充

1. **单层级导航**：侧边栏列表只渲染当前文件夹内容（无展开/折叠、无缩进递归）；点文件夹进入，↑ 返回上一层；当前层级条目标记浅橙选中底。
2. **选中态**：侧边栏当前文件夹行高亮（沿用 `SIDEBAR_ACTIVE_RAIL` 浅橙底）；主区浏览模式中当前目录无额外选中。
3. **新建流程**：`+ 新建 → 文件夹/文档/画板` 在当前层级就地插入一行内联输入框，`Enter` 确认 / `Esc` 取消（复用 `WikiCreateModal` 逻辑改为内联版）。
4. **拖拽移动**：侧边栏条目拖到文件夹行 = 移动；主区浏览模式支持把文档拖入文件夹卡片。
5. **删除**：删除非空文件夹时二次确认并提示「将连同 N 个子项移入回收站」（复用 `KnowledgeSoftDeleteNodes`，去掉 space 参数）。
6. **搜索**：侧边栏与主区搜索同域（当前层级，同一输入联动）；全库搜索走命令面板，结果分组展示路径，点击 `revealPath` 直达。
7. **快捷键**：`⌘N` 在文档管理焦点下新建文档；`Esc` 关闭菜单。
8. **深目录保障**（20+ 层）：
   - 渲染：任意深度只渲染当前 1 层，`O(当前层条目)`；无整树递归，无展开状态持久化负担（`expandPersist` 退役）。
   - 面包屑：`>3 段` 折叠为 `根 ▸ … ▸ 当前`；`…` 点击弹出祖先跳转菜单（全量祖先、可滚动）。

   - 定位：`revealPath` 支持从任意深度直达（搜索、命令面板、深链粘贴）。

## 8. 边界情况

- **空库**：根目录空 → 浏览模式显示引导空状态，侧边栏只显示根（导航条置灰）。
- **深目录（20+ 层）**：侧边栏任意深度只渲染当前 1 层；面包屑超 3 段折叠为 `…` 并可点出祖先跳转菜单；hover 显示完整路径 tooltip。
- **重名**：同目录下重名文件夹/文档新建时自动追加序号（与现 space 重名校验对齐）。
- **删除根**：根目录不可删除；删除顶层文件夹提示影响范围。
- **迁移中断**：v1 备份保留，启动时检测 `migrationDone=false` 则重试或提示。
- **双链/引用**：旧「空间名」前缀的 wiki 链接在迁移时改写为新路径。
- **回收站**：从空间维度回收站改为纯节点维度（已具备 `doc/folder` 两种）。
