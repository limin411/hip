Document Management · V2 Roadmap

文档管理 × Notion：对比与改进方案

以 Notion 为参照系，从 10 个维度盘点 hip「文档管理」模块的差距（现状 v1.2：单层级目录导航 + BlockNote 编辑器 + 双链/图谱 + 版本/回收站），输出 V2 改进提案。基准验收样例：Notion 上的《智能体 Harness 工程研究报告》（长文 + Mermaid + 表格）。

hip 文档管理 · 本地优先 Notion · 云端协作 Spec：docs/doc-manager-vs-notion/spec.md 样例文档：智能体 Harness 工程研究报告 本轮不做：数据库视图 · 导入导出 · AI · 云端 · 评论 · 备份 · 置顶

1定位声明与维度得分

对比前提：hip 是「本地优先的单用户 AI 工作台文档模块」，Notion 是「云端多人协作 + 数据库的知识平台」。范围决策（v1.2）：不做数据库视图、导入导出、AI 文档功能、云端能力、本地评论、自动备份、置顶；V2 聚焦「把已有能力暴露出来 + 编辑器补齐 + 大文档性能」，不牺牲 Markdown 落盘与离线可用。

hip 文档管理

  • 存储 = Markdown + YAML frontmatter，用户拥有数据
  • 单层级目录导航、深目录（20+ 层）、revealPath 直达
  • BlockNote 块编辑 + 双链/反链/图谱 + Mermaid/数学/代码高亮
  • 每日/手动版本、回收站+保留期、模板、AI 文档动作
  • 不可让渡：Markdown 可读 · 离线可用 · Agent 原生集成

Notion

  • 云端块存储（私有格式），随处访问、实时协作
  • 数据库：属性 + 表格/看板/日历/时间线/画廊多视图
  • 页面提及 + 反链面板 + 悬停预览 + 同步块/模板变量
  • Notion AI：问答 / 总结 / 数据库自动填充
  • 护城河 = 结构化数据库 × 协作；弱项 = 深嵌套找回、离线、速度
结论：按范围收缩决策（v1.2），数据库视图 / 导入导出 / AI 文档功能 / 云端能力 / 本地评论 / 自动备份 / 置顶本轮不做，与 Notion 的差距（数据库 1.5 vs 5、协作 1 vs 5）作为已接受差距记录在案（spec §5），V3 再评估。V2 只剩两件事：① 把已有能力暴露出来——⌘K 统一搜索、最近文档、反链面板（数据层全部就绪，纯 UI 组装）；② 编辑器补齐——分栏 / 块引用 / 同步块 / 模板变量；另含大文档性能优化（P2）。
hip 现状（本地） Notion 差距：大 · 中 · 小 · hip 反超 · 本轮不做

3.3 “验证环”是 harness 的关键差异
许多智能体失败不是“不会做”，而是“做了但没验证”。harness 应内置：输出自检（consistency check）、结果核对（与工具返回比对）、约束检查（格式、政策、权限）、失败重试策略。
