# v0.2 下一个版本规划 —「可达 · 可信赖的工作台」

> 日期：2026-06-15 ｜ 状态：已定方向，待评审 → 转实施计划
> 方法：4 个分析子代理（业务/UI 交互/细节/真机测试）对真实代码取证 → 综合排期 → 对抗式 critique 校正。

## 1. 背景与现状校准

hip 已是一个相当成熟的 macOS 桌面 AI agent 应用（Tauri Rust 壳 + React 前端 ~9.6k LOC +
Node sidecar 跑单条 LangGraph ReAct loop），并能把用户配置的 model+key 推入外部 CLI agent
（Claude Code / Codex / OpenCode）。规划前对代码取证，修正了几处过时认知：

- **树干已与 origin 同步**（`main` 0/0），不是"未推送领先数十个 commit"。
- **旧视觉欠债基本已修**：`--text-tertiary` = `#757575`(≈4.4:1)、Modal 有圆角/边框/阴影、
  active 态 `bg-accent-active`、type scale 已进 `tailwind.config`、message-enter 重放已用
  per-session baseline 修掉、`prefers-reduced-motion` 已加；i18n 三语各 255 键齐平；`src` 无裸 `any`。
- **sidecar 生命周期其实处理得当**：`parent-watch`(stdin EOF) + `idle-watchdog` + 退出/关窗 kill。

因此真正的大洞不在"视觉/稳定性"，而在三处：**新用户无法触达第一条对话**、**已建好的工作台在会话
中途不可达**、**~8 块已发布功能仅靠手动验收、零 e2e**。

## 3. 版本主题与目标

**v0.2「可达 · 可信赖的工作台」**：

1. 让新用户**从启动 → 跑通第一条 agent 对话**（在保留登录门的前提下补上 key 落地）。
2. 让已建好的工作台（git 面板 / diff / 检查点 / 外部 agent）**在会话中途可达、可发现**。
3. 在核心流程下**铺第一张 paid-free 的测试网**（先验证可行性，再铺），把"仅手动验收"从默认门禁里拿掉。
4. 顺手补齐**便宜高杠杆的信赖/一致性**修复（ErrorBoundary、token 漂移守护、删除确认等）。

## 7. 风险与缓解

1. **TEST-1 是测试网的单点依赖**（最高风险）。缓解：先做 §8 的可行性 spike；spike 不通则本版测试退回
   "TEST-2/3 用真实但确定性的 fixture + 手动验收 agent 路径"，不让整条测试线被 TEST-1 拖死。
2. **UX-4 的真实工作量在 UX-4a 的主动刷新管线**，不是 chip 本身——已显式拆开。
3. **BIZ-4 过早当头条**会承诺运行时兑现不了的可靠性。缓解：B2 前置 happy-path 验证，验证不过就只"呈现
   外部 agent"而不放进 onboarding 头条。
4. **范围现实性**：本版仍含 TEST-1(L+) + 多个 M。若人手紧，必保主干 = A1 → BIZ-1 → UX-3 → UX-4 →
   TEST-1+TEST-2+TEST-3 + 便宜 polish；BIZ-4 与 CI 是自然的削减线。

## 8. 待办的可行性 spike（TEST-1，先于实现）

在投入 TEST-1 实现前，用 0.5–1 天验证三个未知：
1. 在 sidecar 加一个 `HIP_MOCK_LLM` 生产侧开关，能把 `RealModelRunner` 换成脚本化 `ModelRunner`。
2. 验证 wdio 能把 `HIP_PROVIDERS_PATH` / `HIP_AUTH_PATH` / `HIP_DB_PATH=:memory:` / `HIP_SCRATCH_ROOT`
   **穿过 tauri 的 externalBin spawn 边界**注入到被拉起的 sidecar。
3. mock 至少能复刻一次 streaming SSE + 一次 tool-call + 一次 `reasoning_content`，让现有 loop 走通。

三点全绿 → 按计划铺 TEST-1/2/3；任一不通 → 走风险 §7.1 的退路。
